# AQUA LIFE — Codex 引き継ぎメモ（2026-11-21）

## 目的
スマートフォン（特にiPhone/Safari）で遊べる、**写実的な2D熱帯魚飼育シミュレーター**。
1990年代の AQUAZONE の「本当に熱帯魚を飼っているような雰囲気」は参考にするが、独立したオリジナル作品とし、既存ゲームの素材・コード・ロゴは流用しない。

## 現状
- 対象：このリポジトリの `aquarium/index.html`（単一HTML + CSS + JavaScript Canvas 2D）
- 公開URL： https://kx5pq610-um.github.io/myfirst-app/aquarium/
- 描画：手描きCanvasのベクター形状を12魚種分用意（`speciesVisual`, `drawFish`, `fishMicroDetails`）。陰影や模様は増やしたが、**ユーザーの評価は「まだ全くリアルではない、絵っぽい」**。
- 水槽：`background`, `landscape`, `naturalScene`、水草・流木・底砂・光。
- 既存ゲームループ：`frame`, `simulate`, `tickFish`, `draw`, `ui`
- 既存機能：魚12種類、餌5種類、個体追加、魚が餌に寄る、水換え、水質・酸素・水温、空腹と健康、成長、グッピー繁殖、シミュレーション速度変更、保存・ロード、魚タップで拡大イラストと個体情報、タップ餌やり、スマホ縦画面。
- セーブキー：`aqualife_prototype_v1`（**既存ユーザーのセーブ互換性を守る**）。
- リポジトリには別のゲームや人体アトラスがある。他のディレクトリやトップページは変更しないこと。

## 最優先の開発目標（ユーザー指示）
**魚を写真に近い質感で表示する。2Dのままでよい。**
ベクター図形の描き込みでは限界があるので、**高精細のオリジナル魚スプライト（透明PNG/WebP）を用いた2Dアニメーション**への移行が第一候補。単に「線やグラデーションを追加」する改修は求められていない。

### 次の実装タスク
1. 現行コード・画面・データの関係を把握し、まず「何がイラストに見えるか」を視覚的に分析する。
2. 魚種に対応した **実写に近い高精細の横向き魚素材**を準備し、実際にアプリ内で使う。魚種間の取り違えをしないこと。
3. 手描き `drawFish` を画像描画へ差し替えるか段階的に置き換える。自然な尾びれ揺れ、上下移動、方向転換、奥行き感（サイズ・ぼかし等）を用意。単純な画像の左右スライドだけでは不十分。可能なら胴体と尾びれのパーツ分離と変形を実装。
4. 魚種12種類（neon, guppy, angel, cory, cardinal, rummy, platy, molly, betta, ram, discus, otocinclus）を維持。特に **グッピー・ベタ・ディスカス**を優先し、色・体形・鰭の質感を重視する。
5. 水槽背景も写真らしい落ち着いた質感に調整。**魚が主役**なので背景のディテールでごまかさない。
6. タップで魚の個体情報・拡大表示する既存機能、餌やり、繁殖、セーブを壊さない。アセットの読込が失敗しても現行ベクター描画へフォールバック。
7. iPhone Safariで縦画面・タップ操作・スクロールを検証。重い端末でも描画が滑らかになるよう画像を事前ロードしてキャッシュ。

### 見た目についての合格条件
- 魚の体が平面的な楕円や単色の三角の組み合わせに見えない。
- 鱗・目・エラ・ヒレの半透明感が魚種ごとに自然で、見分けがつく。
- 背景が透明な魚画像で、水槽に四角い画像の境界や白い背景が出ない。
- 泳いでも画像の輪郭が破綻しない。
- スマートフォンで見ても、タップで魚を観察できる。
- 既存の12種/5種類の餌/水質/育成/保存が維持される。

## 素材と著作権の要件
- 使用権がない写真・画像、他ゲームの魚や背景を流用しない。
- 素材は**自作・利用許諾を確認した画像・生成したオリジナル素材**を使用。必要なクレジットやライセンス表示を残す。
- 既存リポジトリのゲーム・人体アトラスの機能を壊さない。
- 素材がまだない場合は、その事実を明示し、実物の見た目改善が確認できるように素材制作と実装をセットで進める。

## Codex への最初の依頼例
「`aquarium/CODEX_HANDOFF.md` を読み、`aquarium/index.html` をスマホ向けの**写実的2D熱帯魚飼育シミュレーター**に改良してください。魚は絵っぽいベクター形状から高精細スプライト方式に移行し、グッピー・ベタ・ディスカスを最優先に。既存機能を保ち、必要な画像素材は著作権上安全なものだけを使い、iPhoneの表示・動作を確認してPull Requestを作成してください。見た目を画像で比較できるようにしてください。」

## 開発後の確認事項
- JavaScript構文エラーなし、HTTPで正常に読み込める
- Safari狭幅画面で横スクロールやボタン重なりなし
- 魚をタップして拡大・状態表示、空白をタップして餌やり
- 魚追加・水換え・一時停止・保存・再読込
- 画像読み込み失敗時のフォールバック
- 実装変更内容、利用アセットの出所、簡単な動作検証結果をPRに記載
